# R7B final ownership recommendation

**Keep the R7B runtime gate open. Accept the existing numerical restart witness.** Two execution paths actually called a state-dependent time conversion after releasing the shared lock. Two Shadbala helpers held the lock while inheriting data settings. Neither finding establishes an incorrect oscillator value. The smallest defensible change uses the lock and configuration snapshot already in the application.

1. **Which active callers are demonstrably unprotected?** CGVO event search called _utc_display_from_jd six times unowned. SBC sunrise also called _datetime_from_jd_ut unowned. Direct invocation reproduced the same defect for sunset; a production caller of sunset was not found. Ordinary reverse calendar conversions outside the lock need no correction. No unowned sidereal setter or planetary calc_ut was observed.
2. **Which are protected but lack sufficient evidence?** Shadbala rise/set and Chesta execute under the lock but lack an established in-transaction data policy. The batch, aspect, BPHS, CGVO star/eclipses/topocentric and SBC position paths have source or real operation-level ownership evidence. What remains is adversarial verification at the changed transaction boundaries and binding the observed configuration/file/value to the phase sample. Helper probes alone do not establish every desktop route instance.
3. **Which candidates are irrelevant?** None of the 39 is proven to be exclusively test or archived code. Pure julday/revjul calendar operations are irrelevant to configuration interference. Separate worker processes, standalone historical scripts and test-only setters cannot mutate the desktop sidecar's state. The supplemental SBC sites and parameterized doctrine setter do belong to the shared boundary.
4. **What proves effective configuration?** Use an explicitly applied snapshot, exclusive setup-through-use ownership, a discriminating independent witness, returned frame/provider flags, and applicable file identity on the bound transaction. The November records already distinguish three sidereal modes. An internal mode readback is unnecessary.
5. **Which requirements duplicate?** Backend and frontend unconditionally force the same incomplete result, and the enclosing and derived statuses repeat it. Replace these fixed defaults with a scoped backend assessment and frontend validation. Numerical witness, receipt consistency and runtime assurance answer different questions.
6. **Is native numerical restart reproducible?** Yes, for the named UTC, executable and observed precision. Both runs presented the same geometry. The version query is stale and cannot identify source on its own. The evidence does not establish a verified native provenance badge.
7. **What closes the integrity gate?** Correct the two conversion boundaries, make provider/path ownership explicit in strict strength and no-directory handling, pass the bounded ownership/interleaving fixture, then bind qualified runtime evidence and 24 actual inputs to the selected sample. Remove only the reasons whose predicates pass. Verify consumer agreement on positive and negative payloads.
8. **Is performance separable?** Yes. Repeated setup and payload size can be profiled independently after the ownership interval and result semantics are pinned. Speed is not a certification condition. The old timing report measured different code.
9. **What is the minimum additional work?** One focused backend ownership change set with the tests in the correction plan, followed by the assessment/consumer change and one review of their evidence. The two native restarts, three-mode references and independent 24-input reconstruction already exist.
10. **When may R7A resume?** Resume R7A work that depends on trusted astronomy when the intended build meets the preceding gates and the selected sample carries the supported assurance status end to end. Preserve incomplete status for historical or unsupported samples. A new positive native screenshot is needed only to claim that positive native presentation. Performance optimization and another numerical restart campaign are outside the dependency.
